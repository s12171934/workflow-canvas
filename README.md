> Orca CLI와 연결하는 로컬 그래프 캔버스다. 워크플로를 편집하고, Orca Run의 Task 의존 관계를 가져와 각 단계의 실제 실행 상태를 관찰한다.

## 기능

- 노드 종류 — 두 계열이다.
  - 그룹 노드 — 대상은 Orca에 열린 프로젝트 또는 워크트리. 단계를 그룹 안에 끌어 놓으면 들어가고 밖으로 끌어내면 빠진다. 프로젝트 그룹은 중첩하지 않고, 워크트리 그룹은 프로젝트·워크트리 그룹 안에 넣을 수 있다(워크트리 안의 워크트리는 Orca에서 하위 워크트리로 만든다, 최대 4단계). 그룹을 지우면 안의 것은 한 단계 위로 옮겨진다.
  - 워크트리 규칙 — 기존 선택은 고를 때 이름·브랜치를 기록해, 실행 때 없으면 같은 이름으로 다시 만든다. 새로 생성은 이름을 직접 지정·이전 단계 에이전트가 결정(이름 보고 또는 직접 생성)·실행 시 입력 중에서 고른다. 같은 이름·브랜치의 워크트리가 이미 있으면 재사용하고, 병렬 실행 중에도 같은 이름은 한 번만 만든다. 「실행마다 따로 만들기」를 켜면 이름 뒤에 실행 번호를 붙인다.
  - 일반 노드 — 워커, 사용자 개입 게이트, 분기, 워크플로 링크(저장된 다른 워크플로를 그 자리에 펼쳐 실행), 메모(실행과 무관).
  - 메모 그룹 — 노드를 묶어 보여 주기만 하는 크기 조절 상자. 옮기면 안에 든 노드(중심이 안에 있는 단계, 통째로 들어간 그룹)가 함께 움직인다. 실행·작업 위치와 무관하고, 그룹 안에 넣거나 연결할 수 없으며, 지워도 안의 노드는 남는다.
- 모델·추론 수준 — 워커와 판정 전용 워커를 쓰는 분기는 노드마다 모델과 effort(`low`·`medium`·`high`·`xhigh`·`max`)를 고를 수 있다. 비워 두면 기본값(모델 `claude-opus-5-5`, effort 는 모델 기본)을 쓴다. 코디네이터는 단계마다 그 값으로 `worker-start --model … [--effort …]` 를 부르고, 위치·모델·effort 가 모두 직전 단계와 같을 때만 터미널을 이어 쓴다.
- 자연어 생성 — Orca가 Claude 에이전트를 띄워 만든다(캔버스는 모델을 직접 부르지 않는다). 사이드바·빈 캔버스의 「자연어로 만들기」는 요청과 고른 프로젝트를 읽고 단계·연결·지침·분기·게이트를 만든 새 워크플로를 저장해 연다(그룹은 만들지 않는다). 단계 속성의 「자연어로 지침 생성」은 앞뒤 단계와 프로젝트 코드를 읽고 그 단계의 지침(필요하면 이름)을 써서 반영한다. 에이전트는 결과를 캔버스 API로 보내고, 서버가 검증해 틀리면 이유를 돌려줘 에이전트가 고쳐 다시 보낸다.
- 그래프 편집 — 노드 추가, 드래그, 그룹 크기 조절, 연결·연결 설명 편집, 삭제, 확대·축소.
- 문서 저장 — JSON 파일로 로컬 저장·불러오기·가져오기·내보내기.
- Orca 연결 — Run 선택, Task와 의존 관계 자동 배치, 개별 노드의 Task 연결.
- 상태 표시 — 대기·실행 중·확인 필요·완료·실패·상태 미확인·미연결 구분, 병렬 작업 동시 표시.
- 실행 기록 — 한 그래프를 여러 번 실행한 기록을 `executions`로 저장한다. 실행 요청마다 Run이 따로 생기고 실행마다 자기 Run을 기억하므로, 여러 요청의 실행을 한 캔버스에서 함께 관찰한다. 실행 시 입력이 있는 요청의 실행 칩에는 그 입력(예: 티켓 키)이 붙는다. 모아 보기(노드별 실행 칩)와 실행 선택(실행 하나의 상태)을 전환하고, 끝난 실행은 항상 숨긴다.
- 실행 로그 — 상단 `실행 로그`에서 실행 요청별 기록을 본다. 진행 중·완료·실패를 가리지 않고 모두 남으며, 실행별·단계별 최종 결과 표를 보여 준다. 서버가 열린 Run을 10초마다 직접 관찰하므로 캔버스를 닫아 두어도 완료가 기록된다. 요청·브리프·코디네이터 기동·실행 등록·Task 상태 변화·코디네이터의 판단(워커 보고·게이트·오류·마무리 보고)을 시각순으로 보여 주고, 브리프·워커 산출물·보고 파일을 연다.
- 실행 화면 — 실행 중·확인 필요·미확인 노드나 칩을 클릭하면 해당 Task 최신 시도의 워커 터미널을 Orca에서 연다.
- 조회 장애 — 마지막 완료 표시를 재사용하지 않고 상태 미확인으로 전환.
- 실행 — `실행` 버튼(×횟수)이 그래프와 횟수를 담은 브리프로 Orca 코디네이터 에이전트(Claude Opus)를 띄운다. 코디네이터가 Run·Task 생성, 워커 기동, 자연어 조건 판단, 정리를 맡고 실행 목록을 캔버스에 등록한다. 실행 시 입력(워크트리 이름)이 같은 실행이 진행 중이거나 같은 입력의 직전 요청 뒤 60초 안이면 거부한다. 입력이 다르면 동시에 진행한다 — 예를 들어 티켓 키를 입력으로 받는 워크플로는 티켓마다 따로 실행해 병렬로 돌릴 수 있고, 다른 워크플로의 워커가 `POST /api/workflows/:id/execute` 로 티켓마다 실행을 요청할 수도 있다.
- 설정값 — 워크플로마다 환경변수 같은 설정값(키·이름·설명·기본값·필수)을 둔다. 아무것도 선택하지 않았을 때 오른쪽 패널에서 편집한다. 실행 창에서 값을 입력받고, 자동화는 입력한 값을 고정해 매번 쓴다. 단계 지침에 `{{키}}` 로 쓰면 브리프를 만들 때 값으로 바뀌고, 코디네이터 브리프에도 값 목록이 들어간다. 펼치는 링크와 「항목마다 따로 실행」 링크는 같은 키를 선언한 대상 워크플로에 값을 넘긴다. 선언하지 않은 `{{키}}` 가 지침에 있거나 필수 값이 비면 실행 전에 거부한다. 값은 워크플로 파일과 브리프에 그대로 남으므로 비밀값은 넣지 않는다.
- 실행 창 — 실행 버튼은 항상 창을 띄워 실행할 프로젝트(Orca에 열린 프로젝트), 병렬 횟수, 실행 시 입력 워크트리 이름, 설정값, 완료 시 정리(워커 세션 정리·만든 워크트리 삭제·코디네이터 종료)를 받는다. 그룹 밖 단계와 프로젝트를 정하지 않은 새 워크트리는 고른 프로젝트를 쓰고, 코디네이터도 거기서 시작한다. 비워 둔 입력은 실행 중에 코디네이터가 묻는다.
- 자동화 — 실행 창에서 「자동화로 예약」을 고르면 그 설정을 고정한 Orca 자동화(`orca automations`)를 만든다. 예약 시각에 Orca가 띄운 에이전트가 캔버스에서 브리프를 받아 코디네이터가 되므로 그때 캔버스 서버가 떠 있어야 한다. 사이드바에서 일정·다음/마지막 실행을 보고 지금 실행·삭제하며, 자동화가 시작한 실행은 실행 칩과 캔버스 상단에 자동화 이름을 표시한다.
- 작업 위치 — 단계가 든 가장 안쪽 워크트리 그룹, 없으면 프로젝트 그룹, 그것도 없으면 실행 때 고른 프로젝트다.
- 워크플로 링크 — 실행 시 링크 대상의 단계를 펼쳐 Task로 만들고, 링크 노드는 펼친 Task 상태를 모아 보여준다. 「실행 방식」을 「끝날 때까지 대기」(기본)로 두면 링크 뒤 단계가 펼친 단계를 모두 기다리고, 「시작만 하고 진행」으로 두면 링크 앞 단계만 기다려 펼친 단계와 동시에 진행한다(실행은 펼친 단계까지 끝나야 끝난다). 「항목마다 따로 실행」으로 두면 펼치지 않고, 앞에 연결한 워커 하나가 `items: a, b` 로 보고한 항목마다 대상 워크플로를 별도 실행으로 요청한다 — 항목은 대상의 「실행 시 입력」 워크트리 이름이 되므로 대상에 그런 그룹이 정확히 하나 있어야 하고, 한 번에 20개까지, 같은 실행에서 이미 요청한 항목은 다시 띄우지 않는다. 요청이 끝나면 링크는 완료이고 따로 띄운 실행은 기다리지 않는다. 링크 노드에 요청한 항목이 칩으로 보이고, 속성에서 항목을 누르면 대상 워크플로를 연다. 대상 미지정·없는 워크플로·순환·3단계 초과 중첩은 실행 전에 거부한다. 단계가 든 그룹에 대상(또는 생성할 프로젝트)이 없어도 거부한다.
- 실행 경계 — 캔버스 서버는 워커를 직접 띄우거나 멈추지 않는다. 워커 실행·중지, 질문 응답, 승인, 의존성 실행은 코디네이터가 담당한다. 사용자 개입 게이트는 자동 승인하지 않고 결정 게이트로 사용자에게 묻는다.
- 삭제 — 왼쪽 목록이나 상단의 휴지통으로 저장 파일을 지운다. Orca의 Run·Task는 남는다.
- 연결과 분기 — 일반 연결은 모두 병렬이다. 한 단계에 여러 연결이 들어오면 기본은 「모두 필요」로, 앞 경로 하나라도 건너뛰어지면 그 단계도 건너뛴다. 분기에서 갈라진 경로가 다시 모이는 단계는 합류 방식을 「하나라도 오면 진행」으로 둔다. 어느 쪽이든 진행 중인 앞 단계가 모두 끝난 뒤 시작한다.
  - 골라서 진행할 때만 분기 노드를 쓴다. 출력마다 조건과 연결 포트가 있고, `하나만`(배타) 또는 `해당하는 것 모두`(포함)를 고른다.
  - 판정 주체 — 직전 단계 워커(worker_done 첫 줄 `decision:`), 판정 전용 워커, 사용자 중 하나. 코디네이터는 판정하지 않고 결과를 캔버스에 등록한다.
  - 사용자 결정 — 사용자 판정 분기와 게이트(통과·거절)는 앞 단계가 끝나면 캔버스 오른쪽 위 「결정 대기」 카드에 뜬다. 코디네이터는 결정 게이트만 걸고 기다리지 않으며, 30초마다 캔버스에 등록된 판정을 가져가 반영한다. 여러 실행·단계의 결정이 서로 다른 시점에 생겨도 서로 막지 않는다. 코디네이터 터미널에 직접 답해도 된다.
  - 게이트 거절 — 그 뒤 단계는 합류 방식과 관계없이 건너뛴다.
  - 워커에서 묻기 — 게이트의 「묻는 곳」을 「직전 단계 워커의 터미널」로 두면, 앞에 연결된 워커 하나가 작업을 마친 뒤 worker_done 전에 자기 터미널에서 사용자에게 묻는다. 작업 맥락을 가진 워커에게 되묻거나 고쳐 달라고 할 수 있고, 답에 따라 `decision: approve|reject` 로 보고한다. 그 워커가 입력을 기다리는 동안 결정 대기 카드에도 「워커 열기」와 함께 뜨며, 카드에서 먼저 고르면 코디네이터가 워커에게 알려 마무리시킨다. 게이트 앞에 워커가 하나가 아니면 실행 전에 거부한다.
  - 고르지 않은 출력 뒤 단계는 캔버스가 계산해 건너뜀으로 표시한다. 분기 연결은 노란 점선, 실행을 고르면 고른 출력은 밝게, 고르지 않은 쪽은 흐리게 보인다.
  - 연결은 순환할 수 없다(저장 시 거부). 연결 설명은 참고 정보이며 진행 여부를 바꾸지 않는다.
- 이전 문서 — 저장 형식의 `task` 노드는 읽을 때 `worker` 로 바뀐다.
- 호환 범위 — 자체 v1 JSON 형식이며 CC Workflow Studio 파일의 직접 가져오기는 지원하지 않는다.

## 설치와 기동

- 요구 사항 — Node.js 22 이상, npm, 실행 중인 Orca 앱과 버전에 맞는 Orca CLI.
- 설치·빌드·실행:

```sh
npm ci
npm run build
./bin/workflow-canvas
```

- 기본 주소 — `http://127.0.0.1:4318`. Orca 프로젝트의 브라우저 탭에서 연다.
- 개발 — `npm run dev`로 같은 주소에서 개발 서버를 실행한다.
- 포트 변경 — `./bin/workflow-canvas --port 4320`.
- CLI 선택 — `ORCA_CLI_COMMAND` 우선, 개발 환경은 `orca-dev`, Linux 외부 터미널은 `orca-ide`, 그 외는 `orca`.
- 환경 변수 — `WORKFLOW_CANVAS_PORT`, `WORKFLOW_CANVAS_DATA_DIR`, `ORCA_CLI_COMMAND`.
- 저장 위치 — 기본 `<checkout>/.local/workflows/`. 로컬 데이터·캐시·빌드 결과는 git에서 제외한다.
- 저장 데이터 — Task 지침·Run/Task ID가 들어갈 수 있으므로 실제 연결 데이터는 공개 저장소에 추가하지 않는다.

## 사용

1. 노드를 선택해 이름·지침을 편집하고 포트를 연결한다.
2. 왼쪽에서 Orca Run을 선택한다.
3. `Task로 그래프 만들기`로 의존 관계를 가져오거나, 단계 속성에서 기존 노드에 Task를 연결한다.
4. 3초 간격으로 갱신되는 상태를 확인한다.
5. `저장`으로 로컬에 보관한다. 문서 이동 시 JSON 내보내기·가져오기를 사용한다.

## 공개 면

- `bin/workflow-canvas` — 로컬 서버 실행 진입점.
- `exports/workflow.schema.json` — 저장·교환용 JSON Schema. 고유 노드·연결 ID와 참조 무결성도 서버에서 검사한다.
- 저장소 내부 코드 — 외부 도구에서 `src/`·`server/`를 직접 참조하지 않는다.
- 설계와 API — [[40_Tools/workflow-canvas/docs/설계와 연동|설계와 연동]].
